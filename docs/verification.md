# 开发与验收记录

## 电商经营问数助手

| 验收场景 | 输入或注入的故障 | 预期结果 | 证据 |
| --- | --- | --- | --- |
| 业务口径 | 2026-11 华东的订单总数与成交单量 | 5 笔与 3 笔，取消和待支付订单只计入总数 | `analytics/backend/src/main/resources/data.sql`、Java 聚合集成测试 |
| 提交幂等 | 并发发送两次相同问题和同一个幂等键 | 返回同一任务 ID，Agent 执行 1 次。复用键提交不同问题返回 409 | `QueryServiceTest`、`analytics/scripts/smoke.py` |
| SSE 中断 | 从已读事件 2 重新订阅 | 只回放事件 3，浏览器刷新后任务 ID 保持一致 | `QueryEvents`、HTTP 冒烟和浏览器操作 |
| 缓存失联 | 先查两遍，再停 Redis 后提交同一指标 | 首次查库，再次命中。停服后回退数据库，结果仍为 3 笔 | 本地 H2＋真实 Redis 集成，Java 日志及 `source` 字段 |
| 模型工具与兜底 | 输入别名未命中的问题并回放工具建议、畸形参数或超时 | 合法建议须由人确认。失败保留澄清或目录口径 | `analytics/agent/tests/test_plan.py` |

可以口述业务问题：“同样问 11 月华东的订单，订单总数是 5 笔，支付订单是 3 笔。两者都能写成合法 SQL，因此单看 SQL 是否执行成功会漏掉口径错误。用同一批数据展示两种口径，再用人工标定的期望值验收。”

数据为固定样例。缓存键包含数据版本、目录版本、指标、月份和区域，缓存期限 3 分钟。把样例换成实时变化的业务表后，需要另外设计更新和失效策略。任务重启后会标记未完成的单实例任务，用户可重新提交。SSE 事件记录固定为接收、处理中、终态三种，通过任务状态回放。

## MewCode

| 验收场景 | 输入或注入的故障 | 预期结果 |
| --- | --- | --- |
| 协议兼容 | 分别回放 OpenAI 与 Anthropic 的正文、推理和结束事件 | 上层收到正文，保持同一 TUI 流程 |
| 分片 | 把字节流按每 3 字节切分，切开 UTF-8 汉字和事件换行 | 合并后正文仍还原为「你好」 |
| 提前断开 | 已收到半截正文，连接结束前缺少完整结束事件 | 当前界面给出失败提示，对话历史新增 0 条 |
| 分类提示 | HTTP 401、403、404、429、503，或事件内报告错误 | 将异常交给终端界面对应提示，仍可继续使用 |
| 终端操作 | 回车提交一轮，随后 Ctrl+L | 能呈现回复，清空后上下文记录为 0 条 |

12 个 pytest 用例中包含真实的 Textual 测试驱动，协议响应由本地回放。一个适合复述的判断是：“界面可以先显示增量，但完整历史要等协议结束事件。仅看到网络响应结束无法证明模型正常输出完，这个差别用缺失结束事件的测试直接测出来。”
